## 3. 设计模式

### 3.1 仓储模式 (Repository Pattern)
每个数据库表对应一个 Repository 类，封装 CRUD 和业务查询，隔离数据访问逻辑。

### 3.2 MVVM 模式 (WPF 端)
- **Model**: Common 项目中的实体类
- **View**: XAML 页面
- **ViewModel**: ViewModelBase + RelayCommand（代码后置方式简化实现）

### 3.3 服务定位器模式 (WPF 端)
`ServiceLocator` 静态类统一管理 DbContext 和 Repository 的创建，作为轻量 DI 替代方案。

### 3.4 依赖注入 (Web 端)
ASP.NET Core 原生 DI 容器管理 DbContext (Scoped)、Repository (Scoped)、JsonUserService (Singleton)。

## 4. 数据流

### 4.1 入库流程
```
管理员填写表单 → 选择物品 → 输入数量/单价
  → StockInRepository.ExecuteStockInAsync()
    → BEGIN TRANSACTION
    → 生成流水号 SI+yyyyMMdd+序号
    → INSERT StockIn
    → UPDATE Items.Quantity += 入库数量
    → COMMIT
    → (触发器备选：trg_StockIn_AfterInsert)
```

### 4.2 领用审批流程
```
普通用户 → Web 端提交申请 (Status=0)
  → 管理员查看待审批列表
  → 确认：ApproveAsync()
    → BEGIN TRANSACTION
    → UPDATE StockOut SET Status=1
    → UPDATE Items.Quantity -= 领用数量
    → COMMIT
  → 驳回：RejectAsync()
    → UPDATE StockOut SET Status=2
    (不扣减库存)
```

### 4.3 用户管理流程
```
管理员 → 用户维护页面
  → 增删改操作
  → JsonUserService 更新内存列表
  → 序列化写回 Users.json
  → Web 端登录时从 Users.json 读取验证
```

## 5. 会话管理

| 端 | 方式 | 实现 |
|------|------|------|
| WPF 管理端 | 无状态 | 硬编码 admin/0000 登录，登录后切换窗口 |
| Web 普通用户端 | Session | 登录成功写入 UserId/UserName，30 分钟过期 |
