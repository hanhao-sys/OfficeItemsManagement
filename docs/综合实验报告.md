# 实验报告

## 现代软件实验 + 实验六：办公物品管理系统

---

## 一、实验目的

1. 掌握 C# 面向对象编程技术的应用
2. 掌握桌面应用程序开发（WPF / .NET 8）
3. 掌握 Web 应用程序开发（ASP.NET Core Razor Pages）
4. 掌握 ADO.NET / EF Core 的使用
5. 掌握 MySQL 数据库设计与高级 SQL 功能（存储过程、触发器、视图、游标）
6. 理解和实现小型管理信息系统的完整开发流程

## 二、系统需求分析

### 2.1 业务背景

某单位办公物品管理不规范，采购入库依赖纸质登记，领用审批流程混乱，库存信息无法实时掌握。需要一套信息化系统实现办公物品的规范化管理。

### 2.2 角色分析

| 角色 | 登录端 | 职责 |
|------|--------|------|
| 管理员 | WPF 桌面应用 | 用户维护、物品管理、入库登记、领用审批、库存查询 |
| 普通用户 | Web 浏览器 | 查看库存、提交领用申请 |

### 2.3 功能需求

**管理员功能（6 项）：**

| 需求编号 | 功能 | 说明 |
|----------|------|------|
| F1 | 登录 | 验证 admin/0000，用户名密码不能为空 |
| F2 | 用户维护 | 普通用户的增删改，数据存 JSON 文件 |
| F3 | 物品信息 | 增删改物品（含类别单选、产地下拉、图片上传） |
| F4 | 物品入库 | 自动流水号、自动总价、更新库存 |
| F5 | 物品出库 | 查看申请、确认（扣库存）/驳回 |
| F6 | 库存查询 | 库存总览 + 入库明细 + 领用明细（分页） |

**普通用户功能（3 项）：**

| 需求编号 | 功能 | 说明 |
|----------|------|------|
| F7 | 登录 | 验证 JSON 文件中的用户名密码 |
| F8 | 库存查询 | 查看所有物品库存信息 |
| F9 | 领用申请 | 下拉/弹窗选物品、自动流水号、库存校验 |

### 2.4 数据存储要求

- 用户信息存在文件中（JSON 格式）
- 物品、入库、出库等业务数据存储在 MySQL 8.4.8 LTS 数据库中

### 3.3 数据库设计

#### 3.3.1 ER 图

```
Categories ──(1:N)── Items ──(1:N)── StockIn
Origins    ──(松散)──   │
                        └──(1:N)── StockOut
```

系统包含 5 张表：

| 表名 | 说明 | 主键 | 外键 |
|------|------|------|------|
| Categories | 物品类别字典 | Id | — |
| Origins | 产地字典 | Id | — |
| Items | 物品信息 | ItemCode | Category → Categories.Id |
| StockIn | 入库记录 | StockInNo | ItemCode → Items.ItemCode |
| StockOut | 领用记录 | StockOutNo | ItemCode → Items.ItemCode |

#### 3.3.2 完整性约束

全部约束使用前缀命名规范：

| 前缀 | 含义 | 数量 | 示例 |
|------|------|:---:|------|
| PK_ | 主键 | 5 | PK_Items |
| FK_ | 外键 | 3 | FK_StockIn_ItemCode |
| CK_ | CHECK | 6 | CK_Items_Quantity (≥0) |
| UQ_ | UNIQUE | 2 | UQ_Categories_Name |
| IX_ | 索引 | 7 | IX_StockIn_ItemCode |

#### 3.3.3 触发器（4 个）

| 触发器 | 表 | 时机 | 功能 |
|--------|------|------|------|
| trg_StockIn_AfterInsert | StockIn | AFTER INSERT | 入库后自动累加库存 |
| trg_StockIn_AfterDelete | StockIn | AFTER DELETE | 入库删除时回退库存 |
| trg_StockOut_AfterUpdate | StockOut | AFTER UPDATE | 确认领用时自动扣减库存 |
| trg_StockOut_AfterDelete | StockOut | AFTER DELETE | 已确认记录删除时恢复库存 |

#### 3.3.4 存储过程（10 个）

| 存储过程 | 功能 |
|----------|------|
| sp_GenerateStockInNo | 生成入库流水号 |
| sp_GenerateStockOutNo | 生成领用流水号 |
| sp_StockIn | 事务：写入库 + 更新库存 |
| sp_ApproveStockOut | 事务：确认 + 扣库存 |
| sp_RejectStockOut | 驳回领用 |
| sp_StockStatistics | 按类别统计库存 |
| sp_StockInDetail | 入库明细分页 |
| sp_StockOutDetail | 领用明细分页 |
| sp_FixNegativeStock | 游标批量修正负库存 |
| sp_TopCategoryByStockIn | 入库金额分类排行 |

#### 3.3.5 视图（4 个）

| 视图 | 功能 |
|------|------|
| v_StockSummary | 库存总览（含库存等级） |
| v_StockInMonthly | 入库按月统计 |
| v_StockOutSummary | 领用按物品统计 |
| v_ItemFullInfo | 物品完整信息（含入库总额/领用次数） |

## 四、系统详细设计

### 4.1 管理员登录模块

**位置**：`LoginWindow.xaml` + `LoginWindow.xaml.cs`

**设计**：
- 固定验证：用户名=admin，密码=0000
- 空值检查：用户名或密码为空时显示红色错误提示
- 登录成功 → 跳转主窗口，失败 → 显示"用户名或密码错误"

### 4.2 用户维护模块

**位置**：`UserManagementPage.xaml` + `UserManagementPage.xaml.cs`

**存储**：`Users.json`（JSON 文件）

**设计**：
- 左侧 ListBox 显示用户列表，右侧表单编辑
- 新增/编辑自动判断：ID 已存在且输入框可编辑 → 阻止；ID 已存在且不可编辑 → 更新；ID 不存在 → 新增
- 保存前验证用户 ID、密码、姓名不能为空
- 删除前二次确认

### 4.3 物品信息维护模块

**位置**：`ItemManagementPage.xaml` + `ItemManagementPage.xaml.cs`

**存储**：Items 表 + ImageData（LONGBLOB）

**设计**：
- 类别用 RadioButton 单选（6 选 1）
- 产地用 ComboBox 下拉选择（绑定 Origins 表）
- 图片用 OpenFileDialog 选择，预览后以 byte[] 存入数据库
- 支持搜索（按编码或名称模糊匹配）

### 4.4 物品入库模块

**位置**：`StockInPage.xaml` + `StockInPage.xaml.cs` + `StockInRepository.cs`

**设计**：
- 物品通过弹出窗口选择（弹出 DataGrid，非直接输入）
- 总价 = 数量 × 单价，自动实时计算
- 流水号格式：SI + yyyyMMdd + 3位序号
- **事务保护**：`BeginTransactionAsync` → 生成流水号 → INSERT StockIn → UPDATE Items.Quantity → Commit

### 4.5 领用审批模块

**位置**：`StockOutPage.xaml` + `StockOutPage.xaml.cs` + `StockOutRepository.cs`

**设计**：
- 状态筛选：全部 / 待审批 / 已确认 / 已驳回（RadioButton）
- 确认领用：事务写入 — 更新 Status=1 + 扣减库存
- 驳回：仅更新 Status=2，不扣库存
- 状态颜色：申请(橙)、确认(绿)、驳回(红)
- 状态校验：只能处理"申请"状态的记录，防止重复审批

### 4.6 库存查询模块

**位置**：`StockQueryPage.xaml` + `StockQueryPage.xaml.cs`

**设计**：
- Tab 1 库存总览：JOIN Categories 获取类别名，支持类别筛选，零库存标红
- Tab 2 入库明细：分页（每页 20 条），支持按物品编码筛选
- Tab 3 领用明细：分页（每页 20 条），支持按物品编码筛选

### 4.7 用户登录模块（Web 端）

**位置**：`Login.cshtml` + `Login.cshtml.cs`

**设计**：
- 验证 JSON 文件中的用户名密码
- 登录成功 → Session 存储用户信息
- 登录检查页面守卫：未登录自动跳转到登录页

### 4.8 库存查询模块（Web 端）

**位置**：`StockQuery.cshtml` + `StockQuery.cshtml.cs`

**设计**：
- JOIN Items + Categories 查询
- 零库存物品标红
- 登录守卫

### 4.9 领用申请模块（Web 端）

**位置**：`Apply.cshtml` + `Apply.cshtml.cs`

**设计**：
- 物品选择两种方式：下拉框直接选择、弹窗搜索选择（JS 模糊搜索）
- 自动流水号：SO + yyyyMMdd + 序号
- 领用人和日期自动填入
- 提交前校验库存是否充足
- 下方显示"我的领用记录"（状态跟踪）

### 5.3 展示二：触发器自动更新库存

在 Navicat 中直接执行 SQL（绕过所有 C# 代码），验证触发器自动生效：

```sql
-- 1. 查当前库存
SELECT Quantity FROM Items WHERE ItemCode = 'P001';  -- 假设 = 200

-- 2. 直接 INSERT 入库（不经过程序）
INSERT INTO StockIn VALUES ('SITEST0001', 'P001', NOW(), 50, 25.00, 1250.00);

-- 3. 触发器自动执行后库存变为 250
SELECT Quantity FROM Items WHERE ItemCode = 'P001';  -- = 250
```

**结论**：触发器在数据库层独立工作，C# 代码完全不感知。

## 六、实验加分项实现

### 6.1 100 万条记录性能测试

**数据生成**：存储过程 `sp_SeedMillionStockIn` 循环插入 100 万条入库记录

**测试结果**：

| 测试查询 | 耗时 | 说明 |
|----------|:----:|------|
| SELECT COUNT(*) FROM StockIn | ~0.2s | 全表扫描 |
| WHERE ItemCode='P001' | ~0.01s | 走索引 IX_StockIn_ItemCode |
| WHERE PurchaseDate BETWEEN ... | ~0.05s | 走索引 IX_StockIn_PurchaseDate |
| GROUP BY 聚合 | ~0.8s | 全表扫描 + 临时表 |

**优化方案**：添加复合索引 `CREATE INDEX IX_StockIn_Date_Item ON StockIn(PurchaseDate, ItemCode)` 可进一步加速范围查询。

2. **WPF 桌面开发**：掌握了 XAML 布局（Grid/StackPanel/DataGrid/Border）、数据绑定（Binding）、事件驱动（Click/Checked/SelectionChanged）、MVVM 基础
3. **ASP.NET Core Web 开发**：掌握了 Razor Pages（PageModel）、依赖注入（AddDbContext/AddScoped）、Session 管理、中间件管线
4. **EF Core 数据访问**：理解了 DbContext 配置、LINQ→SQL 转换、AsNoTracking 优化、事务管理（BeginTransactionAsync）、实体跟踪状态
5. **MySQL 数据库**：掌握了表设计与范式、约束命名规范、索引策略（覆盖索引/复合索引）、执行计划分析（EXPLAIN）、存储过程（OUT 参数/事务/SIGNAL）、触发器（AFTER INSERT/UPDATE/DELETE）、视图、游标
6. **软件工程**：理解了分层架构（四层分离）、仓储模式（隔离数据访问）、DTO 模式（解耦实体与展示）、异常处理（async void 陷阱/全局兜底）

### 8.3 问题与解决方案

| 问题 | 原因 | 解决 |
|------|------|------|
| async void 异常崩溃 | WPF 中 async void 的异常无法被 try/catch 捕获 | 改用 Dispatcher.InvokeAsync + 全局 DispatcherUnhandledException 兜底 |
| EF Core 实体跟踪冲突 | 单例 DbContext + FindAsync 跟踪 + Update 新实例 | GetByCodeAsync 改用 AsNoTracking，UpdateAsync 前 Detach 已跟踪实体 |
| 100 万条全量加载卡死 | GetAllAsync 加载全部记录 | 新增 GetRecentAsync(50) 仅取最近 50 条 |
| XAML 解析 NullReference | RadioButton Checked 事件早于 DataGrid 创建 | ApplyFilter 开头加 if (DgStockOut == null) return |
| 百万条性能下降 | 100 万条数据下全表扫描 | 建索引 + 分页 + 限制加载量 |
| 连接 MySQL 失败 | Web 项目缺 Pomelo 包引用 | 添加 Pomelo.EntityFrameworkCore.MySql 8.0.0 到 csproj |
| Web 端登录失败 | 管理员新增的用户在两个端不共享 | 统一指向解决方案根目录的 Users.json |
