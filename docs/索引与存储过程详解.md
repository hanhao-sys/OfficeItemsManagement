# 办公物品管理系统 — 索引与存储过程详解

---

## 第一部分：索引详解

---

### 1.1 什么是索引

索引相当于书的**目录**。没有索引，MySQL 需要逐页翻完整本书（全表扫描）；有了索引，直接定位到章节（索引查找）。

```
无索引：SELECT * FROM StockIn WHERE ItemCode = 'P001'
        → 扫描全部 100 万行，耗时 ~0.2 秒

有索引：同上查询
        → 通过 B+Tree 直接定位，耗时 ~0.01 秒（快 20 倍）
```

### 1.2 本系统 7 个索引逐一说明

---

#### IX_StockIn_ItemCode（StockIn 表，ItemCode 列）

```sql
CREATE INDEX IX_StockIn_ItemCode ON StockIn(ItemCode);
```

| 项目 | 说明 |
|------|------|
| **索引类型** | 普通索引（B+Tree） |
| **为什么建** | 入库明细页面需要"按物品编码查询入库记录"，这是最高频的查询条件 |
| **命中场景** | `WHERE ItemCode = 'P001'`、`JOIN ... ON StockIn.ItemCode = Items.ItemCode` |
| **性能对比** | 100 万条数据：无索引 0.2s → 有索引 0.01s |
| **EXPLAIN 验证** | `type=ref, key=IX_StockIn_ItemCode, rows≈100,000`（与实际命中率有关） |

---

#### IX_StockIn_PurchaseDate（StockIn 表，PurchaseDate 列）

```sql
CREATE INDEX IX_StockIn_PurchaseDate ON StockIn(PurchaseDate);
```

| 项目 | 说明 |
|------|------|
| **索引类型** | 普通索引（B+Tree） |
| **为什么建** | 入库明细支持按日期排序（ORDER BY PurchaseDate DESC）和按日期范围筛选 |
| **命中场景** | `WHERE PurchaseDate BETWEEN '2025-01' AND '2025-06'`、`ORDER BY PurchaseDate DESC` |
| **性能对比** | 日期范围查询：无索引全表扫描 → 有索引只扫描指定范围 |

---

#### IX_StockOut_ItemCode（StockOut 表，ItemCode 列）

```sql
CREATE INDEX IX_StockOut_ItemCode ON StockOut(ItemCode);
```

| 项目 | 说明 |
|------|------|
| **命中场景** | 领用明细按物品编码查询、JOIN Items 获取物品名称 |
| **使用频率** | 中等——领用明细页面查询 |

---

#### IX_StockOut_ApplicantId（StockOut 表，ApplicantId 列）

```sql
CREATE INDEX IX_StockOut_ApplicantId ON StockOut(ApplicantId);
```

| 项目 | 说明 |
|------|------|
| **命中场景** | `WHERE ApplicantId = 'user01'`——Web 端"我的领用记录"查询 |
| **为什么重要** | 每个普通用户登录后都会查自己的领用记录，这是高频查询 |

---

#### IX_StockOut_Status（StockOut 表，Status 列）

```sql
CREATE INDEX IX_StockOut_Status ON StockOut(Status);
```

| 项目 | 说明 |
|------|------|
| **命中场景** | 管理员筛选"待审批"记录：`WHERE Status = 0` |
| **为什么重要** | 管理端"物品出库"页面的默认筛选，且 Status 的基数极低（仅 3 个值：0/1/2），索引效率取决于数据分布 |

> ⚠️ 低基数列（只有 3 个值的列）上建索引的效果取决于数据分布。如果大部分记录 Status=1（已确认），筛选 Status=0（待审批，可能只占 1%）时索引效果很好。MySQL 优化器会根据统计信息自动决定是否使用索引。

---

#### IX_Items_Category（Items 表，Category 列）

```sql
CREATE INDEX IX_Items_Category ON Items(Category);
```

| 项目 | 说明 |
|------|------|
| **命中场景** | 库存总览按类别筛选：`WHERE Category = 1`（只看纸张类） |

---

#### IX_Items_ItemName（Items 表，ItemName 列）

```sql
CREATE INDEX IX_Items_ItemName ON Items(ItemName);
```

| 项目 | 说明 |
|------|------|
| **命中场景** | 管理端搜索物品：`WHERE ItemName LIKE '%打印%'` |
| **注意事项** | `LIKE '%xxx%'` 左右都有通配符时无法走索引，但 `LIKE 'A4%'` 前缀匹配可以走索引 |

---

### 1.3 索引全景图

```
表                 索引                      查询场景
─────────────────────────────────────────────────────────────
StockIn     IX_StockIn_ItemCode        按物品查入库记录
            IX_StockIn_PurchaseDate    按日期范围查询、排序

StockOut    IX_StockOut_ItemCode       按物品查领用记录
            IX_StockOut_ApplicantId    查某用户的领用记录
            IX_StockOut_Status         筛选待审批/已确认/已驳回

Items       IX_Items_Category          按类别筛选库存
            IX_Items_ItemName          按名称搜索物品
```

### 1.4 索引的代价

索引不是免费的，需要权衡：

| 代价 | 说明 |
|------|------|
| **磁盘空间** | 7 个索引额外占用约 40MB（100 万条数据下） |
| **写性能下降** | 每次 INSERT/UPDATE/DELETE 都要同步维护索引 |
| **查询优化器开销** | 查询时优化器要评估用哪个索引 |

本系统以**读为主**（查询远多于写入），索引带来的查询加速远超写入开销，是可接受的设计。

## 第二部分：存储过程详解

---

存储过程是**预编译的 SQL 语句集合**，保存在数据库服务器上，通过名称调用。本系统共 10 个存储过程。

### 2.1 sp_GenerateStockInNo / sp_GenerateStockOutNo — 流水号生成

```sql
CREATE PROCEDURE sp_GenerateStockInNo(OUT outNo VARCHAR(20))
BEGIN
    DECLARE prefix VARCHAR(10);
    DECLARE seq INT;
    SET prefix = CONCAT('SI', DATE_FORMAT(NOW(), '%Y%m%d'));
    SELECT COUNT(*) + 1 INTO seq
    FROM StockIn WHERE StockInNo LIKE CONCAT(prefix, '%');
    SET outNo = CONCAT(prefix, LPAD(seq, 3, '0'));
END
```

**执行过程演示**（假设当天已有 4 条入库）：

```
① prefix = 'SI20250115'                   ← CONCAT('SI', 当前日期)
② SELECT COUNT(*)+1 FROM StockIn
   WHERE StockInNo LIKE 'SI20250115%'      ← 统计当天记录数+1
   结果：seq = 5
③ outNo = 'SI20250115005'                  ← CONCAT + LPAD 补零到 3 位
```

**关键技术点**：

| 技术 | 代码 | 作用 |
|------|------|------|
| CONCAT | `'SI' + 日期` | 拼接流水号前缀 |
| DATE_FORMAT | `NOW(), '%Y%m%d'` | 当前日期转 20250115 格式 |
| LIKE | `'SI20250115%'` | 前缀匹配统计当天条数 |
| LPAD | `(5, 3, '0')` | 5 → '005'，补零到 3 位 |
| OUT 参数 | `OUT outNo` | 把结果传回调用者 |

领用流水号逻辑完全相同，只是前缀改为 `SO`。

### 2.2 sp_StockIn — 入库事务（最核心的存储过程）

```sql
CREATE PROCEDURE sp_StockIn(
    IN p_ItemCode VARCHAR(20),
    IN p_PurchaseDate DATETIME,
    IN p_Quantity INT,
    IN p_UnitPrice DECIMAL(18,2)
)
BEGIN
    DECLARE v_StockInNo VARCHAR(20);
    DECLARE v_TotalPrice DECIMAL(18,2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;       -- 任何错误 → 回滚
        RESIGNAL;        -- 把错误向上抛出
    END;

    START TRANSACTION;
        -- 步骤①：生成流水号
        CALL sp_GenerateStockInNo(v_StockInNo);

        -- 步骤②：计算总价
        SET v_TotalPrice = p_Quantity * p_UnitPrice;

        -- 步骤③：写入库记录
        INSERT INTO StockIn (StockInNo, ItemCode, PurchaseDate,
                             Quantity, UnitPrice, TotalPrice)
        VALUES (v_StockInNo, p_ItemCode, p_PurchaseDate,
                p_Quantity, p_UnitPrice, v_TotalPrice);

        -- 步骤④：更新库存
        UPDATE Items SET Quantity = Quantity + p_Quantity
        WHERE ItemCode = p_ItemCode;

        -- 步骤⑤：返回流水号
        SELECT v_StockInNo AS StockInNo;
    COMMIT;
END
```

**事务保护示意**：

```
START TRANSACTION
    ├── 生成流水号            ──┐
    ├── INSERT StockIn          ├── 三个操作打包
    └── UPDATE Items.Quantity   ──┘
COMMIT    ← 全部成功才提交

如果任何一步失败：
    → EXIT HANDLER 捕获 SQLEXCEPTION
    → ROLLBACK（撤销已执行的操作）
    → RESIGNAL（让程序层也能感知错误）
```

**为什么要用存储过程而不是程序代码**：

| 存储过程 | 程序代码（EF Core） |
|----------|---------------------|
| 一次网络往返 | 至少 3 次网络往返 |
| 预编译，执行快 | 每次生成 SQL |
| 数据库层权限控制 | 需要表级写权限 |
| 本系统作为备选方案 | 实际主用的是 Repository 层事务 |

### 2.3 sp_ApproveStockOut — 确认领用

```sql
CREATE PROCEDURE sp_ApproveStockOut(
    IN p_StockOutNo VARCHAR(20),
    IN p_Approver VARCHAR(50),
    IN p_Remark VARCHAR(500)
)
BEGIN
    -- 步骤①：读取领用记录，获取物品编码和数量
    DECLARE v_ItemCode VARCHAR(20);
    DECLARE v_Quantity INT;
    DECLARE v_Status INT;
    SELECT ItemCode, Quantity, Status
    INTO v_ItemCode, v_Quantity, v_Status
    FROM StockOut WHERE StockOutNo = p_StockOutNo;

    -- 步骤②：状态校验——已处理的不能重复确认
    IF v_Status != 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '该申请已处理，不能重复确认';
    END IF;

    -- 步骤③：事务更新
    START TRANSACTION;
        UPDATE StockOut
        SET Status = 1, ApproveDate = NOW(), Remark = p_Remark
        WHERE StockOutNo = p_StockOutNo;

        UPDATE Items
        SET Quantity = Quantity - v_Quantity
        WHERE ItemCode = v_ItemCode;
    COMMIT;
END
```

**SIGNAL 的作用**：主动抛出异常，阻止重复审批。`SQLSTATE '45000'` 是用户自定义异常的通用代码。

---

### 2.4 sp_RejectStockOut — 驳回领用

```sql
CREATE PROCEDURE sp_RejectStockOut(
    IN p_StockOutNo VARCHAR(20),
    IN p_Remark VARCHAR(500)
)
BEGIN
    UPDATE StockOut
    SET Status = 2, ApproveDate = NOW(), Remark = p_Remark
    WHERE StockOutNo = p_StockOutNo AND Status = 0;
END
```

| 对比确认 | 说明 |
|----------|------|
| 不需要事务 | 单条 UPDATE，成功就成功，无需回滚 |
| 不扣库存 | 驳回只是标记状态，物品数量不变 |
| `AND Status = 0` | 防止对已处理的记录重复驳回 |

### 2.5 sp_StockStatistics — 按类别统计库存

```sql
CREATE PROCEDURE sp_StockStatistics()
BEGIN
    SELECT
        c.Name AS CategoryName,
        COUNT(i.ItemCode) AS ItemCount,
        COALESCE(SUM(i.Quantity), 0) AS TotalQuantity
    FROM Categories c
    LEFT JOIN Items i ON c.Id = i.Category
    GROUP BY c.Id, c.Name
    ORDER BY TotalQuantity DESC;
END
```

**LEFT JOIN 的意义**：使用 LEFT JOIN 确保即使某个类别下还没有物品（如"礼品"类暂无物品），也会显示一行，数量为 0。

**结果示例**：

| CategoryName | ItemCount | TotalQuantity |
|-------------|-----------|---------------|
| 文具 | 3 | 880 |
| 纸张 | 2 | 350 |
| 刀具 | 2 | 180 |
| 单据 | 1 | 200 |
| 礼品 | 1 | 100 |
| 其它 | 1 | 50 |

### 2.6 sp_StockInDetail — 入库明细分页查询

```sql
CREATE PROCEDURE sp_StockInDetail(
    IN p_ItemCode VARCHAR(20),   -- 物品编码筛选（空=全部）
    IN p_PageNo INT,             -- 页码（从 1 开始）
    IN p_PageSize INT            -- 每页条数
)
BEGIN
    DECLARE v_Offset INT;
    SET v_Offset = (p_PageNo - 1) * p_PageSize;

    SELECT si.StockInNo, si.ItemCode, i.ItemName,
           si.PurchaseDate, si.Quantity, si.UnitPrice, si.TotalPrice
    FROM StockIn si JOIN Items i ON si.ItemCode = i.ItemCode
    WHERE (p_ItemCode = '' OR si.ItemCode = p_ItemCode)
    ORDER BY si.PurchaseDate DESC
    LIMIT p_PageSize OFFSET v_Offset;
END
```

**分页计算**：

```
第 1 页 → OFFSET = 0    → 取 1-20 条
第 2 页 → OFFSET = 20   → 取 21-40 条
第 3 页 → OFFSET = 40   → 取 41-60 条
```

**WHERE 条件技巧**：`(p_ItemCode = '' OR si.ItemCode = p_ItemCode)`——传空字符串表示不过滤，传具体编码则精确匹配。一个参数实现"全部/筛选"切换。

### 2.7 sp_FixNegativeStock — 游标修正负库存

```sql
CREATE PROCEDURE sp_FixNegativeStock()
BEGIN
    -- 声明游标变量
    DECLARE done INT DEFAULT 0;
    DECLARE v_ItemCode VARCHAR(20);

    -- 定义游标：查询所有库存为负的物品
    DECLARE cur CURSOR FOR
        SELECT ItemCode FROM Items WHERE Quantity < 0;

    -- 游标遍历结束时设置 done = 1
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;

    -- 打开游标，开始逐行处理
    OPEN cur;
    read_loop: LOOP
        FETCH cur INTO v_ItemCode;         -- 取一行
        IF done THEN LEAVE read_loop;      -- 取完了 → 退出
        END IF;
        UPDATE Items SET Quantity = 0
        WHERE ItemCode = v_ItemCode;       -- 归零
    END LOOP;
    CLOSE cur;
END
```

**游标执行流程**：

```
OPEN cur (打开游标)
    ↓
LOOP 开始
    ↓
FETCH → 取第一条 (Quantity < 0 的物品)
    ↓
UPDATE 归零
    ↓
FETCH → 取下一条
    ↓
...重复...
    ↓
NOT FOUND → done=1 → LEAVE 退出
    ↓
CLOSE cur (关闭游标)
```

**为什么用游标而不是一条 UPDATE**：这是为了演示实验六要求的游标功能。实际生产中，下面这条 SQL 就能完成同样的事情：

```sql
UPDATE Items SET Quantity = 0 WHERE Quantity < 0;
```

游标的适用场景是**无法用一条 SQL 完成的行级复杂逻辑**（如每行需要调用外部接口、每行的处理逻辑不同等）。

### 2.8 sp_TopCategoryByStockIn — 入库金额分类排行

```sql
CREATE PROCEDURE sp_TopCategoryByStockIn(IN p_TopN INT)
BEGIN
    SELECT
        c.Name AS CategoryName,
        COALESCE(SUM(si.TotalPrice), 0) AS TotalAmount,
        COUNT(DISTINCT si.StockInNo) AS InCount
    FROM Categories c
    JOIN Items i ON c.Id = i.Category
    JOIN StockIn si ON i.ItemCode = si.ItemCode
    GROUP BY c.Id, c.Name
    ORDER BY TotalAmount DESC
    LIMIT p_TopN;
END
```

| 调用 | 结果 |
|------|------|
| `CALL sp_TopCategoryByStockIn(3)` | 返回入库金额最高的 3 个类别 |
| `CALL sp_TopCategoryByStockIn(6)` | 返回全部 6 个类别的排行 |

## 第三部分：索引与存储过程的协同

```
用户操作                     使用的存储过程                   依赖的索引
─────────────────────────────────────────────────────────────────────
管理员入库        → sp_StockIn（或 EF Core 事务）     → PK_StockIn（流水号主键）
                                                       IX_StockIn_ItemCode（查询当天序号）

管理员审批确认    → sp_ApproveStockOut               → PK_StockOut（定位记录）
                                                       IX_StockOut_Status（筛选待审批）

入库明细分页查询  → sp_StockInDetail                  → IX_StockIn_ItemCode（按物品筛选）
                                                       IX_StockIn_PurchaseDate（ORDER BY）

领用明细分页查询  → sp_StockOutDetail                 → IX_StockOut_ItemCode
                                                       IX_StockOut_ApplicantId

Web 端"我的记录"  → EF Core LINQ 查询                 → IX_StockOut_ApplicantId

库存总览          → sp_StockStatistics                → IX_Items_Category
```
